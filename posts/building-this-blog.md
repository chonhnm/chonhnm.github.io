这个博客围绕三个目标搭建：

1. **写作简单**：文章直接使用 Markdown 维护。
2. **归档清晰**：通过 tag 快速组织主题。
3. **界面克制**：采用接近 GitHub 的色彩与卡片布局，让内容成为主角。

## 为什么要加标签

随着文章增多，只按时间线浏览会越来越低效。  
标签页可以把相近主题聚合起来，比如 `Next.js`、`Haskell`、`Design`。

## 为什么要支持 Markdown 上传

很多文章会先在本地编辑器里完成，再上传到站点预览。  
上传页解决的是“先看效果，再决定是否发布”的问题。

## 现在的内容结构

- `/posts`：正式博客文章
- `/notes`：短内容与草稿式记录
- `/tags`：标签聚合页
- `/upload`：本地 Markdown 预览页
